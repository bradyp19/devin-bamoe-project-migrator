## What this repo is

Not an application — a migration workspace. The deliverable is a migrated Kogito/Quarkus project under `v9-projects/`, produced by executing `bamoe-v8-to-v9-migration-plan.md` (Prerequisites + Sub-Tasks 1–10, each with Intent / Expected Outcomes / Todo List / Knowledge Sources / Status). `migration-inventory.md` is the Sub-Task 1 audit output that later sub-tasks rely on.

Current state: every sub-task in the plan is marked `[x] done` for the `evaluation` process (`v8-projects/v8-app` → `v9-projects/v9-app`). Migrating a new v8 project means a new `v8-projects/v8-<name>/` source, a new `v9-projects/v9-<name>/` output, and resetting/re-running the plan's sub-tasks for it — confirm with the user before resetting status lines.

## The v9 app (`v9-projects/v9-app`)

- No hand-written Java in `src/main` — the process `evaluation.bpmn` is turned into REST endpoints (e.g. `POST /evaluation`) by Kogito code generation at build time. Process IDs must therefore be codegen-safe (camelCase).
- `src/main/resources/custom-forms-dev/*.tsx|.config` are forms generated by BAMOE Developer Tools (replacing v8 `.frm`); `META-INF/processSVG/` holds the diagram for the process-svg addon.
- `src/test/java/evaluation/EvaluationProcessTest.java` is a `@QuarkusTest` + RestAssured end-to-end test that drives the full process lifecycle over REST. Run it with `mvn test -Dtest=EvaluationProcessTest` from `v9-projects/v9-app/`.
- The `dev` Maven profile is active by default and adds H2 + `bamoe-quarkus-devui`; `-Dnative` enables a native build.
- `pom.xml` currently pins `version.bamoe` to `9.6.0-ibm-0004` (Quarkus `3.33.3.2`), even though a nearby comment and the plan refer to 9.5.x. Resolving these requires the BAMOE Maven repository configured in `~/.m2/settings.xml` (see the plan's Prerequisites); dependency resolution failures usually mean that repo isn't set up rather than a pom bug.
